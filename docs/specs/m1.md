# M1 명세: 봉 통계

M1은 공개 시세에서 봉을 받아 PC에 보관하고, 기간별 봉 통계와 장기 보유 대 단기 매매 지표(봉 계산 재료)를 화면에 보인다. 여기에 알림센터와 디스코드 보내기, 비밀 값 가리기를 더한다. exe에서 보이는 결과는 다음과 같다. 처음 설정에서 코인과 알림 보관 기간을 고르면 현황 화면에 코인별 통계와 지표가 보인다. 알림센터의 여섯 탭에 알림이 쌓이고, 주소를 넣은 탭의 알림은 디스코드로 간다.

근거: `docs/product-rules.md`(아래 "N절"), `docs/screen-design.md`(아래 "설계서 N"), `docs/specs/m0.md`(아래 "M0 명세 N"), `CLAUDE.md`, `.github/workflows/`. 거기 있는 규칙과 모습은 옮기지 않고 가리킨다.

팀이 만들고 시험하는 것은 모두 만든 숫자와 가짜로 한다. 실제로 봉을 받는 것은 사용자 PC의 exe뿐이다. 세션은 거래소 API를 부르지 않는다(`CLAUDE.md`).

## 1. 범위

넣는 것:

- 공개 시세에서 원화 마켓 코인 목록(유의·주의 표시 포함)과 봉을 받아 PC에 보관한다(5.7절, 7절, 12절). Open API로만 받는다. 공식 SDK와 예제 코드는 복사하지 않는다.
- 기간별 봉 통계(3.5)와 지표의 봉 계산 값(3.6)을 계산해 현황 화면에 보인다(7절, 설계서 4). 미완성 봉의 표시와 "보장하지 않는다"는 글도 넣는다.
- 처음 설정과 설정 화면에서 코인 고르기와 알림 보관 기간 고르기(1절, 3절의 목록 순서, 6절, 설계서 3, 6). 그 밖의 칸은 넣지 않는다.
- 알림센터: 현황 화면 안의 여섯 분류 탭, 알림 저장, 보관 기간이 지난 알림 지우기(6절, 11절, 12절, 설계서 8).
- 디스코드: 탭마다 웹후크 주소 칸, 주소를 Windows 자격 증명 보관소에 두기, 보내기, 보내지 못했다는 표시(6절, 9절, 11절).
- 비밀 값과 가리기(9절, 3.10).
- M1에 생기는 알림(3.9)과 화면에 꼭 적는 디스코드 글 두 문장(11절, 설계서 10.2의 마, 바). 처음 설정 화면의 투자 자문 글(M0 명세 2절)은 남긴다.

넣지 않는 것:

- AI 보고서와 지표의 AI 의견(M2).
- 회차와 판단 일정, 주문, 손절, 한도, 멈춤과 긴급 정지, 상태 띠, 모의매매, 계정 읽기, 지표의 매매 기록 비교(M3).
- 유의·주의 표시로 새 매수를 막는 것(M3, 5.7절).
- 트레이, 시작 앱, 절전과 다시 켜기 처리(M4).
- 실거래와 업비트 키(M5, M6).
- Windows 알림(11절). 생기는 마일스톤은 정해지지 않음(7절의 물음 1).
- 보고서, 기록 화면의 내용. 두 자리는 M0 명세 2절의 빈 글 그대로다.

## 2. M1에서만 쓰는 모습

아래는 M1에서만 쓰는 모습이고 뒤 마일스톤이 바꾼다. 규칙은 바꾸지 않는다. 설계서 15에도 같은 말로 적는다.

1. 봉을 받는 때: 3절의 회차가 없으므로 M1은 네 때에 받는다. (가) 창이 뜬 직후, 처음 설정을 마쳤으면, (나) 코인 목록을 저장한 직후, (다) 현황 화면에서 "다시 시도"를 눌렀을 때, (라) 켜져 있는 동안 앞 받기가 끝난 때부터 60분마다. 7절의 "회차마다 새로 생긴 봉만 받는다"와 "저장된 마지막 봉은 다음 회차에 다시 받아 덮어쓴다"는 "회차"를 이 받는 때로 읽어 따른다. M3에서는 회차가 받는 때가 된다.
2. A-1의 글: 설계서 12의 A-1 글은 회차와 판단을 말한다. M1에서는 "{코인}: 봉 통계를 만들지 못했습니다({오류 이름})."로 보인다.
3. 일시 차단: 공개 시세에서 "일시 차단"(11절)을 받으면, M1에서는 오류 멈춤 대신 봉 받기만 멈춘다. 멈추는 동안은 응답이 준 기다릴 시간만큼이고, 없으면 5분, 10분, 20분, 40분, 60분으로 늘린다. 차단이 끝나면 다음 받는 때에 다시 받는다. 받지 못한 코인마다 A-1(오류 이름 "일시 차단")이 생긴다. 차단 중에 "다시 시도"를 누르면 화면에 "거래소가 잠시 요청을 막았습니다. {시각} 뒤에 다시 받습니다."가 보이고 요청은 나가지 않는다.
4. "알림 {n}건": 상태 띠는 M3에 생긴다. M1과 M2에서는 아직 보지 않은 알림이 있으면 화면 이름 목록의 "현황" 뒤에 " ({n})"이 붙는다. 누르면 현황 화면이 열리고 설계서 8.2의 규칙대로 탭이 골라진다.
5. 알림에 적는 모드: M1에는 모드를 고르는 곳이 없다. 9절의 "처음 켤 때의 모드는 모의매매"를 따라 알림의 모드는 모두 "모의매매"다.
6. 디스코드 글(설계서 10.2의 마, 바): 처음 설정 화면 10 자리에 가(투자 자문), 마, 바를 이 순서로 보인다. 나, 다, 라(손절, 절전, 자동 주문)와 "위 내용을 읽었습니다" 고르기는 그 기능이 생기는 마일스톤에 넣는다.
7. 유의·주의: 코인 목록에서 그 코인 옆에 "유의·주의"를 경고 색으로 붙인다. 설계서 3.4의 "이 코인은 유의·주의 표시가 있어 새로 사지 않습니다."는 매수를 막는 M3에 넣는다.
8. 처음 설정: M1에서 처음 설정을 마쳤다는 것은 코인 하나 이상과 알림 보관 기간을 저장한 것이다. 처음 설정 화면의 12 버튼은 "저장하고 시작"이다. 이 버튼은 코인과 보관 기간이 골라져 있을 때만 누를 수 있다. 누르면 두 값과 "M1 처음 설정 끝남"을 저장하고 현황 화면으로 간다. 그 뒤로는 켤 때 현황 화면이 먼저 보인다(설계서 13.2). M3에서 나머지 칸이 생기면 M1에서 저장한 코인과 보관 기간이 그 칸에 채워진 채 보이고, 처음 설정을 다시 마쳐야 하는지는 M3 명세가 정한다(3.7의 `first_setup_level`).
9. 현황 화면: 코인 칸에는 코인, 지표, 기간별 통계만 보인다. 보유, 주문, 손절선, 오늘 요약, 지금 회차, 모의 운영은 M3에서 생긴다.

- 시험 폴더: `tests/unit/`(백엔드), `tests/ui/`(화면), `tests/trading/`(거래), `tests/acceptance/`와 `tests/conftest.py`(품질·빌드), `tests/fakes/`(3.13).

### 3.4 공용 타입(`core/`, 백엔드가 먼저 올린다)

모두 표준 라이브러리만 쓰는 frozen dataclass와 enum이다. 가격과 수량은 `decimal.Decimal`, 시각은 UTC가 붙은 `datetime`이다.

- `AlertCategory`(`StrEnum`): `TRADE="trade"`, `REPORT="report"`, `LIMIT="limit"`, `HOLDING="holding"`, `ERROR="error"`, `OTHER="other"`. 정의 순서가 11절의 순서이고, 이름은 `ALERT_CATEGORY_TITLES`(매매 알림, 보고서 알림, 제한 알림, 보유 알림, 오류 알림, 기타 알림)다.
- `Mode`(`StrEnum`): `PAPER="paper"`, `LIVE="live"`. 화면의 글은 "모의매매", "실거래"다. M1은 `PAPER`만 쓴다(2의 5).
- `CandleUnit`(`StrEnum`): `DAY="day"`, `MINUTE_60="minute60"`.
- `Candle`: `market: str`, `unit: CandleUnit`, `start: datetime`, `open`, `high`, `low`, `close`, `volume`, `value: Decimal`(거래대금). `start`는 봉의 시작 시각이다.
- `Market`: `market: str`(예: `KRW-AAA` 꼴), `name: str`, `caution: bool`(유의·주의 표시).
- `PeriodStats`, `CandleIndicator`: 3.5, 3.6.
- `LoadState`(`StrEnum`): `LOADING`, `READY`, `NO_DATA`, `FAILED`.
- `CoinView`: `market`, `state: LoadState`, `periods: tuple[PeriodStats, ...]`, `indicator: CandleIndicator | None`, `last_incomplete: bool`, `fetched_at: datetime | None`, `error_name: str | None`, `blocked_until: datetime | None`.
- `MarketsView`: `state: LoadState`, `markets: tuple[Market, ...]`, `error_name: str | None`.
- `SettingsView`: `coins: tuple[str, ...]`(설정 목록 순서), `retention_days: int | None`(7, 30, 90 가운데 하나. 고르기 전에는 `None`), `first_setup_done: bool`.
- `AlertDetail`: `stage: str`, `coin: str | None`, `error_name: str`, `content: str`, `after: str`. 오류 알림과 기타 알림에만 있다(11절).
- `AlertView`: `id: int`, `created_at: datetime`, `mode: Mode`, `category: AlertCategory`, `code: str`(예: `A-1`), `coin: str | None`, `text: str`, `detail: AlertDetail | None`, `seen: bool`, `discord_failed: bool`.
- `AlertsView`: `alerts: tuple[AlertView, ...]`(새것이 앞), `unseen: Mapping[AlertCategory, int]`, `state: LoadState`.
- `WebhookView`: `category: AlertCategory`, `saved: bool`, `message: str | None`(칸 아래 글. 설계서 8.4).
- `SaveResult`: `target: str`(`"settings"`, `"webhook"`), `ok: bool`, `message: str | None`.
- `UiUpdate` = 위 `*View`와 `SaveResult` 가운데 하나.
- `UiActions`(`typing.Protocol`): 3.8의 동작.
- `Clock`(`Protocol`): `now() -> datetime`(UTC), `monotonic() -> float`, `sleep(seconds: float) -> None`. 진짜는 `SystemClock`이다.
- `KST = timezone(timedelta(hours=9))`. 한국 시간은 운영체제의 시간대 설정을 읽지 않고 이 값으로만 바꾼다. Ubuntu와 Windows에서 같은 결과가 나온다.
- `is_webhook_url(text: str) -> bool`(3.9), `redact(text: str, secrets: Iterable[str], env: Mapping[str, str]) -> str`(3.10).
- 화면 글로 쓰는 값(분류 이름, 단계 이름, 오류 이름)은 `core`의 상수로 두고, 화면과 조립이 같은 상수를 쓴다.

### 3.5 기간별 봉 통계(7절)

| 기간 | 봉 단위 | 쓰는 봉 |
|---|---|---|
| 전체 | 일봉 | 저장된 완성된 일봉 전부 |
| 1년 | 일봉 | 마지막 완성된 일봉에서 거슬러 365개 시작 시각 안에 든 봉 |
| 3개월 | 일봉 | 같은 꼴로 90개 |
| 1개월 | 일봉 | 같은 꼴로 30개 |
| 1주 | 60분봉 | 마지막 완성된 60분봉에서 거슬러 168개 시작 시각 안에 든 봉 |

- 완성된 봉만 계산에 쓴다. 봉의 시작 시각에 단위(1일, 60분)를 더한 때가 지금(`Clock.now()`)보다 뒤이면 미완성이다(7절). 일봉은 한국 시간 09:00에 바뀐다(7절).
- 체결이 없어 봉이 없는 구간(7절)은 채우지 않는다. 있는 봉만으로 계산하고, 그 기간의 봉 수를 함께 보인다.
- 기간 안의 봉이 2개보다 적으면 그 기간은 "봉이 모자람"으로 두고 값을 보이지 않는다. 다섯 기간이 모두 모자라면 통계를 만들지 못한 것이다(A-1, 오류 이름 "봉이 모자람").
- 계산은 `Decimal`(정밀도 28자리)로 하고, 비율은 소수 넷째 자리(0.01%)에서 반올림(`ROUND_HALF_EVEN`)한다. 가격은 받은 값 그대로다.

`PeriodStats`의 항목(봉은 시작 시각 순, 첫 봉 f, 마지막 봉 l):

| 항목 | 계산 |
|---|---|
| `period`, `unit`, `count` | 기간 이름, 봉 단위, 쓴 봉 수 |
| `first_start`, `last_start` | 첫 봉과 마지막 봉의 시작 시각 |
| `open_price`, `close_price` | f의 시가, l의 종가 |
| `change` | `close_price ÷ open_price − 1` |
| `high`, `low` | 봉들의 고가 가운데 가장 큰 값, 저가 가운데 가장 작은 값 |
| `from_high` | `close_price ÷ high − 1`(0 이하) |
| `max_drawdown` | 종가를 차례로 볼 때 그때까지의 가장 큰 종가에서 떨어진 비율 가운데 가장 큰 것(0 이하로 적는다) |
| `volatility` | 이웃한 두 봉의 종가 변화율(`c[i] ÷ c[i−1] − 1`)들의 모표준편차 |
| `up_ratio` | 종가가 시가보다 높은 봉의 수 ÷ `count` |
| `avg_value` | 봉 거래대금의 평균(원) |

화면에 보일 항목(설계서 4.2의 8): 기간, 봉 수, `change`, `high`, `low`, `from_high`, `max_drawdown`, `volatility`, `up_ratio`. `open_price`, `close_price`, `avg_value`, 시각은 M2의 AI 입력에 쓰고 화면에는 보이지 않는다.

### 3.6 지표의 봉 계산 값(7절)

`CandleIndicator`(M2가 AI 입력에 그대로 쓴다. 7절, 8절):

| 필드 | 화면 이름 | 계산 |
|---|---|---|
| `trend_1y` | 1년 변화 | 1년 기간의 `change` |
| `trend_3m` | 3개월 변화 | 3개월 기간의 `change` |
| `vs_ma20` | 20일 평균 대비 | 마지막 완성된 일봉 종가 ÷ 마지막 20개 완성된 일봉 종가의 평균 − 1 |
| `vs_ma120` | 120일 평균 대비 | 같은 꼴로 120개 |
| `volatility_1y` | 1년 일간 변동성 | 1년 기간의 `volatility` |
| `volatility_1w` | 1주 시간 변동성 | 1주 기간의 `volatility` |
| `max_drawdown_1y` | 1년 최대 낙폭 | 1년 기간의 `max_drawdown` |

- 재료가 모자란 필드(봉 수가 모자람)는 `None`이고 화면에는 "봉이 모자람"이 보인다.
- `items() -> tuple[tuple[str, str], ...]`: (화면 이름, 보이는 값) 쌍을 위 순서로 돌려준다. 비율은 "+12.34%" 꼴이다. M2는 이 쌍을 AI 입력 글로 쓴다.
- 지표는 계산 결과를 보일 뿐이다. 어느 쪽이 이득인지 판정하는 필드나 글은 두지 않는다(7절).

### 3.7 저장(`storage/`, 스키마 1)

- 스키마를 올리는 함수는 `storage.database.migrate(conn) -> int`다. M0의 `app.db`(`user_version` 0)를 표 셋을 만들어 1로 올리고, 이미 1이면 그대로 둔다. 하나의 트랜잭션 안에서 하고 `PRAGMA user_version`을 1로 쓴다. 이 앱이 아는 것보다 큰 번호면 `StorageError`를 낸다. `SCHEMA_VERSION = 1`이다. 표는 STRICT로 만든다. WAL과 synchronous=FULL(12절, M0 명세 3.6)은 그대로다.
- 표 `settings`: `key TEXT PRIMARY KEY`, `value TEXT NOT NULL`. 키: `coins`(마켓 코드를 설정 목록 순서로 담은 JSON 배열), `retention_days`(`"7"`, `"30"`, `"90"`), `first_setup_level`(M1이 마치면 `"1"`).
- 표 `candles`: `market TEXT`, `unit TEXT`, `start_utc TEXT`(ISO 8601, 초까지, `Z`), `open`, `high`, `low`, `close`, `volume`, `value`(모두 `Decimal`의 글로 저장하는 `TEXT`), `PRIMARY KEY (market, unit, start_utc)`. 같은 키는 덮어쓴다(7절).
- 표 `alerts`: `id INTEGER PRIMARY KEY`, `created_utc TEXT`, `mode TEXT`, `category TEXT`, `code TEXT`, `coin TEXT`(없으면 NULL), `text TEXT`, `stage`, `error_name`, `content`, `after`(오류 알림과 기타 알림에만, 그 밖에는 NULL), `seen INTEGER`(0 또는 1), `discord_failed INTEGER`(0 또는 1), `discord_state TEXT`(`"not_sent"`, `"sent"`, `"failed"`, `"no_address"`). 본 알림은 저장한다. 다시 켜도 본 알림의 표시가 남는다.
- 웹후크 주소는 어느 표에도 쓰지 않는다(9절).
- 받은 봉은 자료 폴더의 `app.db`에만 둔다(7절, 12절).

### 3.8 조립과 화면의 연결점

- `UiContext`에 `actions: UiActions | None = None`을 더한다. `None`이면 화면은 동작을 부르지 않는다. 그래서 M0 시험처럼 `UiContext("0.0.1", "X")`로 만들어도 된다.
- `create_main_window(context) -> MainWindow`. `MainWindow`는 `QMainWindow`이고, `apply(update: UiUpdate) -> None`을 가진다. `apply`는 Qt의 주 스레드에서만 부른다.
- `UiActions`의 동작. 모두 Qt의 주 스레드에서 부른다. 일을 큐에 넣고 바로 돌아오며, 결과는 `apply`로 온다.

| 동작 | 결과로 오는 것 |
|---|---|
| `refresh_markets()` | `MarketsView` |
| `save_settings(coins: tuple[str, ...], retention_days: int, *, first_setup: bool)` | `SaveResult("settings", …)`, `SettingsView`, 코인이 바뀌었으면 받기 시작(2의 1) |
| `retry_candles()` | `CoinView`들 |
| `save_webhook(category: AlertCategory, url: str)` | `SaveResult("webhook", …)`, `WebhookView` |
| `delete_webhook(category: AlertCategory)` | `SaveResult("webhook", …)`, `WebhookView` |
| `mark_seen(alert_ids: tuple[int, ...])` | `AlertsView` |

- 화면은 `save_webhook`을 부르기 전에 `is_webhook_url`로 확인하고, 형식이 아니면 부르지 않고 설계서 6.3의 경고 글을 보인다. 부른 뒤에는 입력 칸을 비운다. 주소 글을 화면의 다른 곳, 로그, 기록에 두지 않는다.
- 스레드: 일하는 스레드는 둘이다. 둘 다 `app`이 만들고, 끝낼 때 멈춘다.
  - 자료 스레드: SQLite 연결 하나를 이 스레드만 연다. 동작 큐, 받기(2의 1), 통계 계산, 알림 저장과 지우기를 맡는다.
  - 보내기 스레드: 디스코드 보내기와 보관소 읽고 쓰기를 맡는다. 자료 스레드는 보낼 알림의 id와 가린 글만 넘긴다. 보낸 결과는 큐로 자료 스레드에 돌려주고, 자료 스레드가 `discord_state`를 쓴다.
- 두 스레드는 `UiUpdate`를 `app`의 다리 객체(PySide6의 시그널, 큐 연결)에 넣는다. 다리가 주 스레드에서 `window.apply`를 부른다. 화면과 다리 말고는 Qt 객체를 다른 스레드에서 만지지 않는다.

### 3.10 비밀 값, 가리기, 가짜를 넣는 길

- 보관소(`vault/`): `keyring`의 서비스 이름은 `coin-report-trader`, 사용자 이름은 `discord-webhook:{분류 값}`(예: `discord-webhook:error`)이다. Windows에서는 Windows 자격 증명 보관소(keyring의 Windows 백엔드)만 쓴다. 그 밖의 백엔드가 골라지면 쓰지 않고 "주소를 저장하지 못했습니다."를 보인다(설계서 8.4).
- 주소는 보내기 스레드가 보내기 직전에 보관소에서 읽는다. 자료 스레드, DB, 로그, 알림, 화면의 글, 예외 글에 두지 않는다(9절).
- 가리기(`core.redact`): 오류 글, 거래소 응답, 디스코드 응답을 화면, 기록, 로그, 알림에 쓰기 전에 거친다(9절). 순서는 아래와 같다.
  1. 웹후크 주소 꼴(3.9의 꼴을 글 가운데에서 찾는 것)과 넘겨받은 비밀 값을 "(가려서 보임)"으로 바꾼다.
  2. 경로를 M0 명세 3.5의 보여 주는 꼴로 줄인다. `LOCALAPPDATA` 아래는 `%LOCALAPPDATA%`로, `XDG_DATA_HOME` 아래는 `$XDG_DATA_HOME`으로, `HOME` 아래는 `~`로 바꾼다. 그 밖에 드라이브 문자 다음 `Users` 폴더, `/home`, `/Users` 바로 아래의 사용자 이름은 `~`로 바꾼다.
  3. 2,000자에서 자른다.
  - 함수는 같은 입력에 운영체제와 상관없이 같은 글을 낸다(경로 꼴은 `\`와 `/`를 모두 본다).
- 가짜를 넣는 길: `main(argv=None, *, services: Services | None = None)`, `run_gui(argv=None, *, services=None)`, `run_self_test(..., services=None)`. `Services`(`app/services.py`)의 필드는 `quote: QuoteSource`, `webhook: WebhookSender`, `vault: SecretStore`, `clock: Clock`이다. `None`이면 진짜를 쓴다. 세 Protocol은 `core`에 둔다(3.4와 함께 1번이 올린다). exe를 가짜로 돌리는 명령줄 옵션이나 환경 변수는 두지 않는다.

### 3.11 `--self-test`

M0 명세 3.8의 다섯 항목(`import`, `qt`, `sqlite`, `paths`, `notice`)에 두 항목을 더해 일곱이다. 네트워크를 쓰지 않고 보관소에 읽고 쓰지 않는다.

| 키 | 점검 | 통과 조건 |
|---|---|---|
| `import` | M0의 목록에 더해, 패키지의 새 폴더 전부와 `httpx`, `certifi`, `keyring` | 전부 import된다. `app/self_test.py`의 `SUBPACKAGES`, `THIRD_PARTY_MODULES`를 넓힌다(4절의 19번) |
| `sqlite` | 임시 폴더의 DB를 열고 `migrate` | `wal`, `2`, `user_version` 1, 표 셋 |
| `tls` | `certifi`의 인증서 묶음을 읽어 TLS 설정을 만든다(연결하지 않는다) | 묶음 파일이 있고 CA 인증서가 하나 이상이다. exe이면 묶음이 번들 안에 있다 |
| `vault` | keyring 백엔드의 종류만 본다 | Windows이면 Windows 백엔드다. 그 밖의 운영체제에서는 판정하지 않고 통과로 적는다 |

- `qt`, `paths`, `notice`는 M0 명세 3.8 그대로다. 항목의 차례는 `import`, `qt`, `sqlite`, `paths`, `notice`, `tls`, `vault`다.
- 결과의 마지막 줄은 `결과: 통과 (7/7)`이다.
- TLS 설정은 `legacy/src/autotrader/adapters/tls.py`의 방식을 따른다(최소 TLS 1.2, 호스트와 인증서 확인). 보고서에는 묶음의 파일 이름만 쓴다.

### 3.12 의존성(버전)

- Python, PySide6-Essentials, 개발 그룹: M0 명세 5절 그대로다.
- 런타임에 더한다: `httpx>=0.28,<0.29`(공개 시세와 디스코드. 동기 `httpx.Client`를 각 스레드에서 쓴다), `certifi>=2026.1`(인증서 묶음), `keyring>=25.7,<26`(Windows 자격 증명 보관소).
- pytest 설정에 `pythonpath = ["tests"]`를 더해 시험이 `tests/fakes/`를 `import fakes.…`로 받게 한다(3.13).
- 확인 결과: 풀림. 저장소 밖 임시 폴더에서 지금의 `pyproject.toml`과 `uv.lock`에 위 셋만 더해 `uv lock`을 돌렸고, Windows AMD64와 Linux x86_64 두 환경에서 풀렸다. 풀린 버전은 httpx 0.28.1, certifi 2026.10.23, keyring 25.7.0이다. 함께 들어온 것은 anyio, httpcore, h11, idna, jaraco 계열, Windows의 pywin32-ctypes, Linux의 SecretStorage와 jeepney다.

## 5. 완료 기준

- 4절의 30번까지의 PR이 main에 병합되었다.
- main에서 `uv sync --locked`, `uv run ruff check .`, `QT_QPA_PLATFORM=offscreen uv run pytest -q`가 Ubuntu와 Windows에서 통과한다(test, windows 검사).
- `uv run --no-project python scripts/checks/run_all.py`가 0으로 끝난다. import 방향(3.3)과 웹후크 주소 꼴 검사가 통과로 찍힌다(structure 검사).
- windows 검사의 "Build with PyInstaller"와 "Smoke test (--self-test)" 단계가 성공이다. 출력된 `self-test-report.txt`의 마지막 줄은 `결과: 통과 (7/7)`이다.
- `uv run pytest -q`가 B1~B22 표시가 붙은 시험을 모두 모으고 통과한다.
- 시험과 `--self-test`는 네트워크를 쓰지 않고, 진짜 keyring 백엔드를 부르지 않는다(B22, 7번의 장치).

사용자가 PC에서 하는 확인(세션은 하지 않는다). 지휘와 사용자가 아래 차례대로 한다.

1. exe를 얻는다: GitHub의 Actions에서 build-exe 워크플로를 main에 수동으로 돌린다. 올라온 `build-windows-…` 묶음을 받는다(하루 동안 남는다). 19번 뒤에 1~4를, 27번 뒤에 1~8을 한다.
2. 켠다. 처음 설정에서 코인 하나 이상과 알림 보관 기간을 고르고 "저장하고 시작"을 누른다. 현황 화면이 보이면 통과다.
3. 현황 화면의 코인 칸에 지표가 보이고, 기간별 통계 표에 다섯 기간이 보이면 통과다(새로 생긴 코인은 "봉이 모자람"일 수 있다).
4. 끄고 다시 켠다. 현황 화면이 먼저 보이고 통계가 다시 보이면 통과다.
5. 알림센터의 한 탭(예: 오류 알림)에 실제 디스코드 웹후크 주소를 넣고 저장한다. "(가려서 보임) 저장됨"이 보이면 통과다.
6. 네트워크를 끊고 "다시 시도"를 누른다. 오류 알림 탭에 A-1이 생기고, 네트워크를 다시 이은 뒤 그 디스코드 채널에 글이 오면 통과다. 끊긴 동안 보내지 못한 알림이면 "디스코드로 보내지 못함"이 붙는다.
7. 끄고 다시 켠다. 주소가 "(가려서 보임) 저장됨"이고 알림이 남아 있으면 통과다.
8. `%LOCALAPPDATA%\coin-report-trader` 아래 파일(`app.db`, `logs` 폴더)에서 주소의 토큰 일부를 찾아 나오지 않으면 통과다.

실패했을 때는 알림센터 오류 알림 탭의 펼친 글과 `logs\app.log`를 본다. 지휘에게는 몇 번 확인에서 실패했는지, 단계 이름과 오류 이름만 전한다. 실제 시세, 웹후크 주소, 사용자 이름이 든 경로는 전하지 않는다.

## 7. 지휘에게 물을 것

사용자의 뜻이 필요해서 정하지 못한 것이다. 팀은 이 자리를 만들지 않는다.

1. Windows 알림이 생기는 마일스톤. 디스코드 주소가 없는 분류의 알림을 Windows 알림으로 보일지와, 분류마다 켜고 끌지(설계서 16의 16).
2. 예상하지 못한 오류나 저장 실패가 난 뒤에 받기(뒤 마일스톤에서는 회차와 손절 점검)를 계속할지 멈춤으로 들어갈지(11절이 명세 전에 사용자에게 확인받기로 했다. 설계서 16의 17).
3. 알림 보관 기간을 고르기 전에 생긴 알림(창을 띄우기 전에 난 오류, 처음 설정 전의 알림)을 언제 지우는지(설계서 16의 24).
4. 코인 목록 받기의 실패를 알림으로 보일지. 규칙에 "알린다"가 없어 M1은 처음 설정·설정 화면의 상태(설계서 3.4)로만 보인다(설계서 16의 25).
5. 디스코드 웹후크 주소를 지울 때와 알림 보관 기간을 짧게 바꿀 때 확인 창을 둘지(설계서 16의 1).
6. 디스코드로 보내지 못한 알림을 나중에 다시 보내는지와, 다시 보내면 표시가 없어지는지(설계서 16의 23).
7. 주소를 보관소에 저장하지 못한 것이 오류 알림의 저장 실패(A-29)에 드는지(설계서 16의 22). M1은 주소 칸 아래의 글만 보인다.
