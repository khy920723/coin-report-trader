# M0 명세: 바탕

다음 마일스톤들이 올라갈 틀을 만든다. 매매, 통계, AI 기능은 넣지 않는다. exe에서 보이는 결과는 창 하나, 다섯 화면의 빈 자리, `--self-test`다.
근거: `docs/product-rules.md`(아래 "N절"), `CLAUDE.md`, `.github/workflows/`. 거기 있는 규칙은 옮기지 않는다.

## 1. 범위

넣는 것:

- 프로젝트 틀: 루트 `pyproject.toml`, `uv.lock`, `.python-version`, `.gitignore`, 패키지 `src/coin_report_trader/`, `tests/`.
- 프로그램 틀: 진입점, 창 하나, 조립(3.3).
- 저장의 틀: 12절의 방식(WAL, synchronous=FULL)으로 DB 파일을 여는 것까지. 표는 만들지 않는다.
- 다섯 화면의 빈 자리: 11절의 화면 이름(처음 설정, 현황, 보고서, 기록, 설정).
- 검사 스크립트의 틀과 M0 항목(3.7). 실거래 잠금 검사는 M5 명세 전까지 넣지 않는다(9절).
- 패키징 설정, 라이선스 고지, `--self-test`.

넣지 않는 것: 봉 받기와 봉 통계(M1), Claude 호출(M2), 주문·모의매매·손절·계정 읽기(M3), 시작 앱 등록·트레이·절전과 재시작 처리(M4), 실거래(M5부터), 업비트 키를 다루는 것 전부, 알림, 설정 저장, 표(테이블). M0에는 `trading/` 폴더도 만들지 않는다.

## 2. 화면 흐름

1. exe(또는 `python -m coin_report_trader`)를 켜면 창 하나가 뜬다. 창 제목은 `Coin Report Trader`다.
2. 창 왼쪽(또는 위)에 다섯 화면의 이름이 이 순서로 있다: 처음 설정, 현황, 보고서, 기록, 설정. 고르면 오른쪽 자리가 바뀐다. 켰을 때 보이는 자리는 처음 설정이다.
3. 각 자리에는 화면 이름을 제목으로, 아래 문구를 본문으로 보인다: "이 화면은 아직 비어 있습니다."
4. 처음 설정 자리에는 위 문구 밑에 11절의 문구 하나를 더 보인다: "이 프로그램은 투자 자문이 아닙니다. AI 판단은 틀릴 수 있습니다."
5. 창 아래 상태 줄에 "바탕 버전 <버전> · 매매 기능 없음 · 자료 폴더 <보여 주는 경로>"를 보인다. 경로는 3.5의 보여 주는 형태로 쓴다.
6. 창을 닫으면 프로그램이 끝난다(트레이는 M4).

11절의 다른 문구(손절, 절전, AI 표시와 출처)는 그 기능이 생기는 마일스톤의 명세에서 넣는다. 화면 점검 모드(13절의 화면 팀 일)는 M0에 넣지 않는다.

## 3. 팀 사이 약속

### 3.1 이름과 폴더

- 패키지 `coin_report_trader`(`src/` 아래). 배포 이름과 exe 이름, 자료 폴더 이름은 `coin-report-trader`, 버전은 `0.0.1`(`coin_report_trader.__version__`). 거래소 상표는 쓰지 않는다(11절).

| 폴더(`src/coin_report_trader/` 아래) | 맡는 팀 | 내용 |
|---|---|---|
| `__init__.py`, `__main__.py` | 백엔드 | 버전, 진입점 |
| `core/` | 백엔드 | 공용 타입과 상수(3.2) |
| `config/` | 백엔드 | 자료 폴더 위치(3.5) |
| `storage/` | 백엔드 | DB 파일 열기(3.6) |
| `app/` | 백엔드 | 조립, GUI 실행, `--self-test` |
| `ui/` | 화면 | 창과 다섯 화면의 자리 |
| `trading/` | 거래 | M3부터. M0에는 없다 |

- 시험: `tests/unit/`(백엔드), `tests/ui/`(화면), `tests/acceptance/`와 `tests/conftest.py`(품질·빌드). 루트 `packaging/`과 `scripts/`는 품질·빌드가 맡는다.

### 3.2 공용 타입(`core/`, 백엔드가 먼저 올린다)

`core/`는 표준 라이브러리만 import한다(PySide6도 쓰지 않는다).

- `APP_ID = "coin-report-trader"`, `WINDOW_TITLE = "Coin Report Trader"`.
- `ScreenId`(`enum.StrEnum`): `FIRST_SETUP="first_setup"`, `STATUS="status"`, `REPORTS="reports"`, `HISTORY="history"`, `SETTINGS="settings"`. 정의 순서가 화면 순서다.
- `SCREEN_TITLES: Mapping[ScreenId, str]`: 처음 설정, 현황, 보고서, 기록, 설정.
- `UiContext`(frozen dataclass): `version: str`, `data_dir_display: str`.

### 3.3 조립과 창의 연결점

- 화면이 만든다: `coin_report_trader.ui.create_main_window(context: UiContext) -> QMainWindow`.
  - 부르기 전에 `QApplication`이 있어야 한다. 함수는 `QApplication`을 만들지 않고, 창을 띄우지(`show`) 않으며, 파일·DB·네트워크를 쓰지 않는다.
  - 돌려주는 창: `objectName`은 `mainWindow`, 제목은 `WINDOW_TITLE`이다. 다섯 자리를 `ScreenId` 순서로 담고, 자리마다 `objectName`이 `screen_<ScreenId 값>`인 위젯이 있다. 2절의 문구를 보인다.
- 백엔드가 부른다: `app.run_gui(argv) -> int`가 자료 폴더를 만들고, 로그를 열고, DB를 열어 확인하고, `QApplication`을 만든 뒤 `create_main_window`로 창을 받아 띄운다. 이벤트 루프가 끝나면 종료 코드를 돌려준다.
- import 방향(검사 스크립트가 확인한다):

| 폴더 | import해도 되는 것 |
|---|---|
| `core` | 표준 라이브러리 |
| `config`, `storage` | `core`, 표준 라이브러리 |
| `ui` | `core`, PySide6, 표준 라이브러리 |
| `trading`(M3부터) | `core`, 표준 라이브러리, 그 마일스톤 명세가 더하는 외부 패키지 |
| `app` | 위 전부(`trading`을 import하는 곳은 `app`뿐이다) |
| `__main__.py` | 표준 라이브러리. `app`은 옵션을 읽은 뒤 함수 안에서 import한다 |

- `app`을 import하는 것은 `__main__.py`뿐이다. `tests/`는 무엇이든 import해도 된다.

### 3.4 진입점과 명령줄

- `python -m coin_report_trader`, `pyproject.toml`의 `[project.gui-scripts]` `coin-report-trader = "coin_report_trader.__main__:main"`, exe는 `packaging/launcher.py`가 `main()`을 부른다(`legacy/packaging/launcher.py`의 이유와 같다).
- `main(argv: Sequence[str] | None = None) -> int`. 옵션: 없음(창 실행), `--self-test`(3.8), `--version`(버전을 보이고 0).
- 모르는 옵션은 종료 코드 2로 끝낸다. 창 모드 exe에서는 `sys.stdout`, `sys.stderr`가 `None`이므로 어떤 경우에도 처리되지 않은 예외나 오류 대화상자가 나오지 않게 한다.

### 3.5 자료 폴더

- Windows: `%LOCALAPPDATA%\coin-report-trader\`. Linux(개발·CI): `$XDG_DATA_HOME/coin-report-trader/`, 값이 없거나 절대 경로가 아니면 `~/.local/share/coin-report-trader/`.
- 안의 파일: `data\app.db`(DB), `logs\app.log`(로그. M0에는 시작과 종료, 오류만 쓴다). 모의와 실거래 기록을 나누는 방식은 M3·M5 명세가 정한다(12절).
- Windows에서 `LOCALAPPDATA`가 없거나 절대 경로가 아니면 다른 곳으로 대신하지 않고 오류로 본다.
- `config.paths.resolve_app_paths(env: Mapping[str, str] | None = None, platform: str | None = None) -> AppPaths`. 인자를 빼면 현재 프로세스 값을 쓴다. `AppPaths`는 `root`, `data_dir`, `logs_dir`, `database_file`, `log_file`, `ensure()`(폴더 만들기, 여러 번 불러도 된다)를 가진다.
- 보여 주는 경로: 화면, 보고서, 로그에는 앞부분을 `%LOCALAPPDATA%` 또는 `~`로 줄인 경로만 쓴다(사용자 이름이 들어가지 않게).
- 시험에서 바꾸는 방법: `resolve_app_paths`에 `env`를 넘기거나, `monkeypatch.setenv`로 `LOCALAPPDATA`(Windows)·`XDG_DATA_HOME`(Linux)를 `tmp_path`로 바꾼다. `tests/conftest.py`의 autouse 픽스처가 모든 시험에서 두 값을 `tmp_path`로 바꾼다. 실제 사용자 폴더를 쓰는 시험은 없다. 자료 폴더를 바꾸는 명령줄 옵션이나 전용 환경 변수는 두지 않는다.

### 3.6 DB 파일 열기

- `storage.database.open_database(path: Path) -> sqlite3.Connection`: 폴더가 있다고 보고 파일을 열어(없으면 만든다) `PRAGMA journal_mode=WAL`과 `PRAGMA synchronous=FULL`을 걸고, 다시 읽어 `wal`과 `2`가 아니면 `StorageError`(`core`)를 낸다. 연결마다 건다.
- 스키마 번호는 `PRAGMA user_version`으로 두고 M0에서는 0이다. 표는 만들지 않는다.

### 3.7 검사 스크립트(`scripts/checks/`, 품질·빌드)

`scripts/checks/run_all.py`가 아래 항목을 모두 돌리고 항목마다 통과·실패를 한 줄씩 쓴다. 하나라도 실패하면 1, 아니면 0으로 끝난다. 항목은 같은 폴더의 모듈로 나눈다.

1. 필수 파일: `pyproject.toml`, `uv.lock`, `.python-version`, `.gitignore`가 있다. `packaging/` 아래 `.spec`는 둘 이상이면 실패다.
2. `legacy/` 제외: `pyproject.toml`의 ruff 설정이 `legacy`를 빼고, pytest `testpaths`가 `["tests"]`다.
3. import 방향: `src/coin_report_trader/`의 `.py`를 `ast`로 읽어 3.3의 표를 어기면 파일과 줄을 적고 실패한다.
4. 개인정보: `git ls-files`의 글 파일(`legacy/`, `packaging/licenses/`, `.github/` 제외. 커밋 이메일은 privacy 검사가 본다)에서 `checks.yml` privacy의 허용 목록 밖 이메일 주소, `C:\Users\<이름>`, `/home/<이름>`, `/Users/<이름>` 꼴의 경로를 찾으면 실패한다. 시험 자료의 가짜 주소는 `example.com`이면 허용한다.
5. 상표: `pyproject.toml`의 `[project].name`, `[project.gui-scripts]`의 이름, `.spec`의 exe 이름에 `upbit`(대소문자 무시)나 `업비트`가 있으면 실패한다.

거래 코드 위치의 세부 검사는 `trading/`이 생기는 M3 명세에서 더한다.

### 3.8 `--self-test`

창을 띄우지 않고 네트워크를 쓰지 않는다. 점검마다 모든 예외를 잡아 실패로 적고, 하나가 실패해도 나머지를 한다(`legacy/src/autotrader/app/self_test.py`의 방식). 점검 항목:

| 키 | 점검 | 통과 조건 |
|---|---|---|
| `import` | 패키지의 모든 모듈, `PySide6.QtCore`·`QtGui`·`QtWidgets`, `sqlite3` | 전부 import된다 |
| `qt` | offscreen 플러그인을 먼저 찾고, `-platform offscreen`으로 `QApplication`을 만들어 `create_main_window` 호출 | 제목, 다섯 자리의 순서와 `objectName`이 3.3과 같고 창이 보이지 않는다 |
| `sqlite` | 임시 폴더의 DB를 `open_database`로 연다 | `wal`, `2`, `user_version` 0. 실제 `app.db`는 건드리지 않는다 |
| `paths` | 자료 폴더를 정해 `ensure()`하고 `root`, `data`, `logs`에 임시 파일을 써 본다 | 쓸 수 있다 |
| `notice` | exe일 때만 exe 옆 `NOTICE.txt`와 `_internal/licenses/` | 있다. 소스 실행이면 판정하지 않고 통과로 적는다 |

- 결과 파일: 현재 폴더의 `self-test-report.txt`, UTF-8(BOM 붙임). 줄: 제목, 버전, 실행 형태(exe 또는 소스), Python, OS, 점검 시각(UTC), 항목마다 `[통과]` 또는 `[실패] <제목>: <설명>`, 마지막 줄 `결과: 통과 (n/n)` 또는 `결과: 실패 (k/n)`. 경로는 3.5의 보여 주는 형태로만 쓴다.
- 종료 코드: 모두 통과하고 파일을 썼으면 0, 아니면 1. 점검 모듈을 import하지 못해도 대신 보고서를 쓰고 1로 끝낸다.

### 3.9 패키징과 고지(품질·빌드)

- `packaging/coin-report-trader.spec` 하나. 폴더형(onedir), 창 모드, UPX 끔. 결과: `dist/coin-report-trader/coin-report-trader.exe`. 저장소 루트에서 `uv run pyinstaller packaging/coin-report-trader.spec --noconfirm --clean`.
- 라이선스 고지: exe 옆 `NOTICE.txt`, 원문과 목록은 `_internal/licenses/`. 대상은 번들에 든 제3자 것(PySide6·Qt의 LGPL-3.0과 GPL-3.0 원문, Python 런타임, PyInstaller 부트로더)이다. 이 저장소의 코드는 라이선스를 두지 않으므로(README) 앱의 LICENSE 파일은 넣지 않는다.
- GPL로만 제공되는 Qt 모듈이 번들에 들어가면 빌드를 멈춘다(`legacy/packaging/autotrader.spec`의 검사를 새 이름으로 옮긴다).

## 5. 버전

- Python `>=3.13,<3.14`, `.python-version`은 `3.13`.
- 런타임 의존성은 `PySide6-Essentials>=6.12,<6.13` 하나다(6.13 이상은 쓰지 않는다). 쓰지 않는 Qt 모듈을 줄이려고 `PySide6` 대신 Essentials를 쓴다.
- SQLite: Python에 든 `sqlite3`를 쓴다. 따로 의존성을 두지 않는다.
- `[dependency-groups]`의 `dev`: `pytest>=9.2`, `pytest-qt>=4.5`, `ruff>=0.17`, `pyinstaller>=6.22,<6.23`. uv는 `dev` 그룹을 기본으로 깔므로 `uv sync --locked`만으로 모두 깔린다.
- 빌드 백엔드: `uv_build>=0.13.7,<0.14`, `[tool.uv.build-backend]` `module-name = "coin_report_trader"`.
- `[tool.uv]` `required-environments`: `sys_platform == 'win32' and platform_machine == 'AMD64'`, `sys_platform == 'linux' and platform_machine == 'x86_64'`.
- ruff: `target-version = "py313"`, `extend-exclude = ["legacy"]`. pytest: `testpaths = ["tests"]`, `qt_api = "pyside6"`.
- 정확한 버전은 `uv.lock`이 고정한다. uv는 CI의 `astral-sh/setup-uv`가 까는 것을 쓴다.
- 확인 결과: 풀림. 저장소 밖 임시 폴더에서 위 설정으로 `uv lock`이 풀렸다(PySide6-Essentials 6.12.0, PyInstaller 6.22.3, pytest 9.2.0, pytest-qt 4.5.0, ruff 0.17.5, Windows AMD64 휠 있음). `uv_build`로 휠 만들기도 됐다.
